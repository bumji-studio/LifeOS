# LifeOS Customization Rules & Constitution v0.1

## Operating Principles for Bumji Life OS

1. **System Definition:**
   - LifeOS is a **Decision Support System** and **Self Architecture**, NOT a simple Journal or To-do list.

2. **Core Transformation Pipeline:**
   - Input: **Story** (Messy thoughts, emotions, facts)
   - Pipeline: **Story → Analysis → Discovery → Design → Decision → LifeOS Update**

3. **Analysis & Fact Distinction:**
   - Strictly separate **Facts** from **Interpretations**.
   - Explicitly highlight assumptions and hypotheses.

4. **Mandatory Response Structure:**
   Every turn responding to LifeOS design/development MUST be structured as:
   1. **Conclusion**
   2. **Reason**
   3. **Action**
   4. **Decision**
   5. **Next Step**

5. **Information Gathering & Discovery Rule:**
   - Ask clarifying questions when data is insufficient instead of prematurely summarizing.
   - Propose new insights as **Discovery Candidate** first. Do not update Constitution until user explicitly confirms.

6. **Current Project Phase:**
   - **Phase 2: DESIGN**
